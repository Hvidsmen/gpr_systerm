# Единая очередь заданий

Раздел «Задания» находится в основном меню. Он объединяет проверку сметчика, замечания планировщику, согласования, уточнение остатков, ежедневный факт и обычные поручения. Доступны фильтры входящих, выданных и всех доступных заданий, вида, статуса и просрочки. Для каждого задания сохраняются исполнитель, автор, срок, объект, версия плана, при необходимости работа и дата факта, комментарии и история действий. Данные ограничены компанией; обычный пользователь видит свои поручения и задания своей роли, администратор — всю очередь компании; наблюдатель — всю очередь без права изменений.

## Проверка и согласование

Назначение сметчика через карточку ГПР или дневного СМГ автоматически создает задание. Из него открывается существующая проверка названий, цен и подработ. В проверке сметчик может создать замечание по плану или отдельной работе и назначить его планировщику. Кнопка отклонения работы также создает замечание. Планировщик исправляет данные и передает результат автору, описав исправления. Сметчик принимает результат и закрывает замечание либо возвращает с комментарием. Пока есть незакрытые замечания к этой версии, подтвердить проверку сметчика нельзя. Автор может отменить утратившее актуальность поручение с обязательной причиной, сохранив историю.

После отправки ГПР сначала создается задание сметчику, если его действующего подтверждения еще нет. Только после подтверждения сметчика одновременно создаются задания трех профильных служб; до этого действия согласования служб заблокированы. При отсутствии единственного пользователя соответствующей роли задание попадает в очередь роли; назначенный сметчик принимает его в работу. Уже выполненная действующая проверка сметчика учитывается автоматически. После четырех согласований появляется задание генеральному директору. Кнопки в заданиях выполняют обычные защищенные действия согласования; произвольно закрыть согласование как обычное поручение нельзя.

При возврате на доработку открытые задания старого раунда отменяются с записью причины, а планировщику создается задание исправить и повторно отправить план. Новый раунд получает собственные задания. Предыдущие решения и переписка остаются в истории. При открытии очереди существующие проверки и согласования восстанавливаются в ней автоматически; ранее утвержденные планы не направляются на согласование повторно.

## Диспетчер и факт

Администратор назначает пользователю роль «Диспетчер» и объекты / субобъекты в карточке пользователя. Диспетчер видит и редактирует факт только на закрепленных объектах. При распределении ГПР на СМГ закрепляйте за диспетчером субобъекты, в которых вводится факт; общие итоги макрообъекта поднимаются через связи СМГ. По каждому объекту ежедневно создается отдельное задание за вчера. Дата по ссылке заполнения фиксируется датой задания; общий экран по умолчанию также предлагает вчера.

Задания появляются при входе диспетчера в интерфейс; администратор может сформировать их для всех диспетчеров компании, открыв очередь. Дубли исключены. При первом включении создаются задания за вчера; далее пропущенные дни с момента последнего формирования догоняются автоматически. Новые задания не заменяют просроченные. Новое назначение объекта начинает очередь с вчера, снятие назначения отменяет открытые задания по объекту и сбрасывает курсор.

Диспетчер сохраняет работы, людей, технику, ГСМ и при необходимости актировку в существующей форме. Затем возвращается в задание, подтверждает проверку четырех разделов и нажимает «Факт заполнен». Система проверяет наличие фактических записей для строк утвержденного оперативного плана на этот день. Ноль вносится явно; отсутствие записи не считается нулем. При актировке с типом и причиной работы допускаются нулевыми, а люди, техника и ГСМ проверяются отдельно. Если плановых строк нет, диспетчер явно подтверждает отсутствие данных для внесения. Это проверка полноты относительно имеющегося плана и подтверждение исполнителя, а не автоматическое определение реального выполнения на объекте.

Изменение, перенос на другую дату / объект или удаление ранее подтвержденного факта снова открывает задание. История прежнего подтверждения сохраняется.

Для фонового формирования без открытия интерфейса можно ежедневно запускать команду из каталога проекта:

```powershell
python manage.py generate_work_tasks
```

Команда идемпотентна и подходит для Планировщика заданий Windows. Она не требует отправки писем или внешних сообщений.

Администратор (роль ADMIN или Django superuser) может выполнять проверку сметчика своей компании: брать общее задание, проверять и исправлять названия, цены и подработы, создавать замечания и подтверждать либо возвращать план. Он может работать и с проверкой, назначенной другому сметчику; назначение при этом сохраняется, а в истории фиксируется фактический исполнитель. Администратора также можно выбрать исполнителем при назначении проверки.

## Проверка месячного ГПР

Для месячного уточнения проверяется только `planning_month`: непустые работы этого месяца и его ресурсы. Для продолжения утвержденного ГПР проверяется новый период от `continuation_start`; прежние месяцы берутся из неизменяемого раунда утверждения. Например, при продолжении января–октября до ноября повторно проверяются и согласуются ноябрьские цифры. В карточке проверки и у согласующих указан период; матрица версии по умолчанию открывается на нем. Полный план доступен через выбор периода.

В проверке есть поиск, фильтры по статусу, разделу и виду работы. Проверенные работы отмечаются зеленым, сворачиваются и перемещаются вниз. Изменение объема за проверяемый период или справочных данных отменяет актуальность отметки. Чекбоксы позволяют проверить несколько работ сразу; «Выбрать все показанные» действует только на строки текущего фильтра. Итоговое подтверждение требует проверки всех работ периода независимо от фильтра.

Доступны два действия над выбранными строками:

- «Объединить в выбранную работу» складывает объемы совместимых работ в одну из выбранных. Должны совпадать объект, единица измерения, вид и состав подработ. Исходные факты и другие версии сохраняются.
- «Объединить выбранные в составную работу» создает новую составную работу; выбранные простые работы становятся подработами. Сметчик задает название, единицу, норматив и профиль каждой подработы. Исходные объемы и дневные строки проверяемого периода сохраняются в подработах; объем основной работы определяется по минимуму выполнения нормативов. Начальная цена — сумма исходных цен на начало периода, умноженных на нормативы; ее нужно проверить. Новая работа требует отдельного подтверждения.

Блок «Похожие по названию» предлагает пары одного типа и единицы измерения. «Выбрать пару» только отмечает строки; итоговую работу и само объединение подтверждает пользователь. Рекомендации не означают, что работы являются дублями.

Объединение в месячном уточнении сохраняет расчетные объемы будущих месяцев. Остатки и история исходных работ остаются в аудите. Если объединены позиции из прогнозных остатков, при последующей сверке их объемы считаются измененными вручную: планировщику нужно проверить итоговую объединенную работу перед допсогласованием. Объединение состава СМГ выполняется через исходный ГПР с последующим обновлением СМГ.

Рекомендации и списки замены общего ГПР включают справочник самого макрообъекта и справочники субобъектов из явно подключенной истории (включая продолжение такого ГПР). В вариантах показаны объект, раздел, ID и сходство названия. Наличие родительской связи само по себе не открывает справочник неподключенного субобъекта. Замечание сохраняет ссылку на исходную позицию без копирования. При фактической замене работа субобъекта копируется в раздел «Справочник · субобъект · раздел» на макрообъекте; связь с оригиналом сохраняется, повторный выбор использует ту же копию. Исторические планы и факты субобъектов не меняются. Уже сопоставленная сама с собой позиция не предлагается.

## Следующий этап после проверки сметчика

После подтверждения проверки планировщик получает задание. Если месячные показатели СМГ совпадают с исходным ГПР, он сохраняет СМГ как оперативный план без дополнительного согласования. Перераспределение между днями само по себе не требует согласования.

При отклонении месячных показателей планировщик отправляет СМГ на согласование: работы, люди и техника согласуются параллельно, затем решение принимает генеральный директор. После утверждения планировщик получает задание применить согласованный СМГ. Во время согласования редактирование закрыто; возврат на доработку требует повторной проверки сметчика. Исходный ГПР сохраняется.

Задания для ранее проверенных черновиков восстанавливаются при открытии списка заданий или запуске generate_work_tasks. Неизмененная действующая проверка повторно не требуется. Требуется миграция planning/0030.

## Последовательность заданий после закрытия месяца

1. С первого числа планируемого месяца — уточнить прогнозный остаток прошлого месяца по закрытому факту и направить корректировку ГПР на допсогласование.
2. Только после утверждения корректировки — системное задание назначенному планировщику актуализировать дневной СМГ. В нем доступны утвержденный ГПР, перечень измененных работ и кнопка создания/открытия отдельной редакции СМГ. Нажатие кнопки не закрывает задание.
3. Планировщик распределяет изменения по оставшимся дням и получает новую проверку сметчика. Далее совпадение месячных итогов с уточненным ГПР разрешает сохранить оперативный план; отклонения требуют согласования трех служб и гендиректора.
4. Применение СМГ автоматически закрывает задание актуализации. До этого оперативным остается прежний СМГ, прошедшие дни и факт сохраняются.

Ключ задания — `smg-update:{carryover_id}:{correction_version_id}`. Оно связано с исходным заданием сверки, новым ГПР и созданной редакцией СМГ; повторная синхронизация не создает дублей. При неактивном исполнителе задание переходит в очередь планировщиков своей компании.

## Служба безопасности

После проверки сметчика ГПР и требующего согласования СМГ параллельно согласуют четыре службы: производство, персонал, техника/ГСМ и СБ (`SECURITY_HEAD`). СБ получает задание, может согласовать или вернуть план с обязательным замечанием; ее решение сохраняется в истории. Генеральный директор получает задание только после всех четырех согласований. Администратор вправе согласовать СБ от своего имени с фиксацией фактического исполнителя.

При обновлении текущие раунды получают дополнительное задание СБ; ранее открытое задание гендиректора приостанавливается и открывается повторно после СБ. Уже утвержденные/завершенные ГПР и примененные СМГ не переоткрываются. Назначьте ответственному пользователю роль «Служба безопасности» в управлении доступом. Если пользователей этой роли несколько, задание находится в общей очереди роли, если один — назначается ему. Требуются миграции accounts/0008 и planning/0032.
