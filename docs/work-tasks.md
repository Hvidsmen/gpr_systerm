# Единая очередь заданий

Раздел «Задания» находится в основном меню. Он объединяет проверку сметчика, замечания планировщику, согласования, уточнение остатков, ежедневный факт и обычные поручения. Доступны фильтры входящих, выданных и всех доступных заданий, вида, статуса и просрочки. Для каждого задания сохраняются исполнитель, автор, срок, объект, версия плана, при необходимости работа и дата факта, комментарии и история действий. Данные ограничены компанией; обычный пользователь видит свои поручения и задания своей роли, администратор — всю очередь компании; наблюдатель — всю очередь без права изменений.

## Проверка и согласование

Назначение сметчика через карточку ГПР или дневного СМГ автоматически создает задание. Из него открывается существующая проверка названий, цен и подработ. В проверке сметчик может создать замечание по плану или отдельной работе и назначить его планировщику. Кнопка отклонения работы также создает замечание. Планировщик исправляет данные и передает результат автору, описав исправления. Сметчик принимает результат и закрывает замечание либо возвращает с комментарием. Пока есть незакрытые замечания к этой версии, подтвердить проверку сметчика нельзя. Автор может отменить утратившее актуальность поручение с обязательной причиной, сохранив историю.

После отправки ГПР на согласование одновременно создаются задания трех профильных служб и сметчика, если его действующего подтверждения еще нет. При отсутствии единственного пользователя соответствующей роли задание попадает в очередь роли; назначенный сметчик принимает его в работу. Уже выполненная действующая проверка сметчика учитывается автоматически. После четырех согласований появляется задание генеральному директору. Кнопки в заданиях выполняют обычные защищенные действия согласования; произвольно закрыть согласование как обычное поручение нельзя.

При возврате на доработку открытые задания старого раунда отменяются с записью причины, а планировщику создается задание исправить и повторно отправить план. Новый раунд получает собственные задания. Предыдущие решения и переписка остаются в истории. При открытии очереди существующие проверки и согласования восстанавливаются в ней автоматически; ранее утвержденные планы не направляются на согласование повторно.

## Диспетчер и факт

Администратор назначает пользователю роль «Диспетчер» и объекты / субобъекты в карточке пользователя. Диспетчер видит и редактирует факт только на закрепленных объектах. При распределении ГПР на СМГ закрепляйте за диспетчером субобъекты, в которых вводится факт; общие итоги макрообъекта поднимаются через связи СМГ. По каждому объекту ежедневно создается отдельное задание за вчера. Дата по ссылке заполнения фиксируется датой задания; общий экран по умолчанию также предлагает вчера.

Задания появляются при входе диспетчера в интерфейс; администратор может сформировать их для всех диспетчеров компании, открыв очередь. Дубли исключены. При первом включении создаются задания за вчера; далее пропущенные дни с момента последнего формирования догоняются автоматически. Новые задания не заменяют просроченные. Новое назначение объекта начинает очередь с вчера, снятие назначения отменяет открытые задания по объекту и сбрасывает курсор.

Диспетчер сохраняет работы, людей, технику, ГСМ и при необходимости актировку в существующей форме. Затем возвращается в задание, подтверждает проверку четырех разделов и нажимает «Факт заполнен». Система проверяет наличие фактических записей для строк утвержденного оперативного плана на этот день. Ноль вносится явно; отсутствие записи не считается нулем. При актировке с типом и причиной работы допускаются нулевыми, а люди, техника и ГСМ проверяются отдельно. Если плановых строк нет, диспетчер явно подтверждает отсутствие данных для внесения. Это проверка полноты относительно имеющегося плана и подтверждение исполнителя, а не автоматическое определение реального выполнения на объекте.

Изменение, перенос на другую дату / объект или удаление ранее подтвержденного факта снова открывает задание. История прежнего подтверждения сохраняется.

Для фонового формирования без открытия интерфейса можно ежедневно запускать команду из каталога проекта:

```powershell
python manage.py generate_work_tasks
```

Команда идемпотентна и подходит для Планировщика заданий Windows. Она не требует отправки писем или внешних сообщений.

Администратор (роль ADMIN или Django superuser) может выполнять проверку сметчика своей компании: брать общее задание, проверять и исправлять названия, цены и подработы, создавать замечания и подтверждать либо возвращать план. Он может работать и с проверкой, назначенной другому сметчику; назначение при этом сохраняется, а в истории фиксируется фактический исполнитель. Администратора также можно выбрать исполнителем при назначении проверки.
