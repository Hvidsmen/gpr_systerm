# Планирование по объектам

Основной процесс планирования на период описан в [рабочем пространстве](period-workspace.md). Ниже — сводные версии ранее утверждённых нижних планов и общие правила учёта.

## Глобальные версии

Откройте **Глобальные версии объектов → Создать версию**, выберите строительный
объект и даты начала/окончания. Версия включает последние утверждённые или
завершённые версии месячных планов этого объекта, пересекающиеся с периодом,
и планы людей, техники и ГСМ за выбранные даты. При необходимости укажите
конкретные утверждённые версии работ. Две версии одного месячного плана
одновременно включить нельзя.

Сначала создаётся черновик. При отправке на согласование фиксируются дневные
планы, нормативы подработ, вид работы, параметр дробных единиц, цены и ресурсные
планы. Изменения текущих ресурсных планов после отправки не меняют снимок.
Утверждает или отклоняет глобальную версию руководитель либо администратор
компании; согласование нижних планов не заменяет это утверждение. После
отклонения повторная отправка обновляет снимок. Утверждённую версию можно
завершить или создать от неё новую редакцию с актуальными утверждёнными
планами. Предыдущая версия сохраняется.

Экран версии показывает дневной план и факт каждой основной работы и ресурсов.
Разные единицы измерения не складываются в общий объём. Факт читается из
текущих производственных записей: исправление прошлого дня меняет результат
на последующих днях, но не плановый снимок. Для каждой работы в снимке сохранены
нормативы и ссылки на версии источников, включая предшествующие периоды,
необходимые для накопительного расчёта.

## Люди, техника и ГСМ

И планы, и факты обязательно относятся к строительному объекту. Прямых полей
проекта, работы и версии месячного плана у ресурсных записей больше нет.

Идентификаторы записи на день:

- Люди: объект + дата + бригада.
- Техника: объект + дата + тип техники + номер машины.
- ГСМ: объект + дата + вид топлива + обозначение техники.

На ресурсных экранах доступны ввод, редактирование, фильтр объекта/даты и
создание планов на диапазон дат. Экран ввода факта из плана запрашивает объект
и дату; подробные часы и ставки вводятся в форме отдельного факта. Создание
плана на период не перезаписывает существующие совпадающие записи: конфликт
показывается в форме, вся операция отменяется.

## Простая работа

Выберите вид **Простая** при создании работы. У неё нет подработ. Месячный
объём распределяется непосредственно в дневные планы работы по календарю
и её профилю нагрузки; без профиля распределение равномерное. При вводе
факта выберите работу, оставьте подработу пустой и укажите выполненный объём.

## Составная работа

Выберите вид **Составная**, добавьте подработы вручную или из шаблона.
У каждой подработы должен быть положительный норматив на одну единицу работы.
Месячный план подработы равен объёму основной работы × норматив.
Стоимость распределяется по весам подработ.

Выполнение основной работы определяется по минимуму:

```
накопительно выполнено = min(накопительный факт каждой подработы / её норматив)
факт дня = накопительно выполнено на этот день − накопительно выполнено ранее
```

Планы рассчитываются таким же способом по дневным планам подработ. Расчёт
начинается с начала истории работы и продолжается через границы месяцев и
глобальных версий. Если одна подработа ещё не выполнена, соответствующие
единицы основной работы не считаются завершёнными.

Параметр **Учитывать дробные единицы** по умолчанию включён. Дробный результат
показывается с точностью до 0,001 единицы, округляя вниз. При выключении
сначала округляется вниз **накопленный** объём основной работы до целого числа,
затем рассчитывается прирост за день. Незавершённые части не теряются.

Пример: для одной единицы работы нужны 2 м подработы A и 3 м³ подработы B.

| Дата | Факт A | Факт B | Накопительно, дробные | За день, дробные | Накопительно, целые | За день, целые |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 31 января | 3 | 0 | 0 | 0 | 0 | 0 |
| 1 февраля | 0 | 2,4 | 0,8 | 0,8 | 0 | 0 |
| 2 февраля | 0 | 2,1 | 1,5 | 0,7 | 1 | 1 |

Чтобы сохранить смысл существующих данных, вид и параметр дробных единиц
работы с фактом или утверждённым планом менять нельзя. Норматив с фактом
или утверждённым планом тоже защищён. Добавлять, удалять или заменять
подработы после появления дневных планов/фактов нельзя; для другой структуры
создайте новую работу. Подработы простой работы и факты составной работы
без подработы отклоняются формой.

## Обновление существующей базы

Остановите сервер и скопируйте **используемую рабочую базу**, прежде чем
выполнять `manage.py migrate`. Миграция изменяет связи и архивирует исходные
ресурсные данные; её автоматический откат не предусмотрен. Для возврата к
предыдущей схеме потребуется резервная копия и предыдущая версия кода.

В PowerShell, если в `.env` задан путь `DJANGO_DB_PATH=data/db.sqlite3`:

```powershell
$backup = "data/db-before-global-planning-$(Get-Date -Format 'yyyyMMdd-HHmmss').sqlite3"
Copy-Item data/db.sqlite3 $backup
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py runserver
```

Если ваша база находится в другом месте, подставьте её фактический путь
в `Copy-Item`. Не заменяйте существующую рабочую базу исходной `db.sqlite3`
из репозитория при обновлении.

Работы, у которых уже есть подработы, становятся составными; остальные —
простыми. Дробные единицы включены по умолчанию.

Ресурсные записи автоматически получают объект, если он однозначно определяется
по старой работе/версии плана либо у старого проекта есть ровно один объект.
Исходные поля **всех** записей сохраняются в журнале переноса. Неоднозначные
привязки и совпадения новых ключей сохраняются там для ручного решения, а не
попадают в рабочие таблицы с произвольным объектом.

Откройте **Перенос ресурсных данных**, назначьте объект каждой ожидающей записи.
Если запись совпадает с существующей, можно явно включить объединение:
объёмы и часы складываются, ставка берётся из формы. Исходные значения
остаются в журнале. Другие компании недоступны в выборе объектов и ресурсов.
Пока есть неразрешённые записи компании, создание/отправка глобального снимка
блокируется, чтобы он не выглядел полным при незавершённом переносе.

В подготовленной облачной копии все 256 ресурсных записей перенесены
автоматически. Рабочая база Windows обновляется отдельно указанными командами.
