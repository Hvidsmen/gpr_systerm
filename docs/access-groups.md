# Группы доступа и Active Directory

Администратор: «Пользователи → Группы доступа и соответствия AD».

1. Создайте группу, например «Диспетчеры КТП».
2. Выберите роль и строительные объекты. Доступ роли сохраняет существующие правила приложения: ограничения назначенными объектами действуют для планировщика (просмотр, создание, ввод, импорт ГПР и СМГ), мастера и диспетчера; прочие роли имеют установленный для них доступ в компании.
3. Выберите сразу нескольких участников. Подходят локальные пользователи и пользователи AD своей компании. Или выберите группу в карточке «Роль и объекты» пользователя.
4. При необходимости укажите полный DN группы AD, полученный у администратора домена, например `CN=GPR-Dispatchers,OU=Groups,DC=yamalgazprom,DC=local`.

Таблица показывает название, роль, объекты, DN AD и количество участников. Изменение роли/объектов группы применяется ко всем участникам сразу. Пустой список объектов для планировщика/диспетчера/мастера не даёт доступа ни к одному объекту. Администраторы управляются индивидуально и не получают административные права через AD.

Один пользователь имеет одну группу доступа: это соответствует существующей модели одной рабочей роли. Несколько групп AD могут быть вложены в указанную группу; AD проверяет транзитивное членство. Если пользователь соответствует нескольким разным группам доступа приложения, вход блокируется до исправления соответствий. Одна группа AD может быть связана только с одной группой приложения.

Соответствие применяется после проверки доменного пароля при каждом входе через AD. Новому пользователю назначаются компания, роль и объекты соответствующей группы. Переход в другую компанию автоматически запрещён. Если ранее автоматически назначенное членство исчезло, группа, роль и объекты снимаются, пользователь попадает на страницу ожидания доступа. Пользователей с индивидуальными/ручными назначениями отсутствие соответствия не меняет.

Изменения членства в AD проверяются при следующем входе; существующие сессии не опрашивают LDAP при каждом запросе. Для немедленного отключения используйте «Активен» в карточке пользователя приложения. Удаление участника из группы через интерфейс снимает у него унаследованную роль и объекты. Доменное членство при этом не меняется и будет вновь применено при следующем входе, пока соответствие существует.

Обновление: применить `python manage.py migrate` и перезапустить приложение. Для входа AD необходимо `LDAP_ENABLED=true` в `.env`, установленный `ldap3` и доступное соединение LDAP. Реальные пароли не хранить в репозитории.

## Поиск групп AD

В форме группы есть список «Найти группу в AD»: при открытии загружаются первые 100 результатов, поиск работает по названию, логину группы и описанию. Кнопка «Найти / обновить» запрашивает актуальные данные AD, выбор подставляет полный DN. Если групп больше 100, уточните поиск; интерфейс явно сообщает об ограничении. Список не записывает и не изменяет группы в самом AD.

По умолчанию группы ищутся во всём настроенном домене (корень строится из `LDAP_DOMAIN`), поскольку они могут находиться за пределами OU пользователей. Чтобы ограничить поиск отдельной OU, задайте `LDAP_GROUP_BASE_DN` в `.env` и перезапустите приложение. Ошибки доступа выводятся рядом со списком. Ручной DN остаётся доступен.

## Назначения планировщика

Роль «Планировщик» ограничена явно назначенными строительными объектами: списки и просмотр ГПР/СМГ, создание рабочих пространств и версий, ввод плана, импорт в план и отчёты. Назначения берутся из карточки пользователя или материализуются из группы доступа. Администратор сохраняет доступ к объектам компании.

Без назначений планировщику не доступны объектные планы. После обновления проверьте назначения у существующих планировщиков. Макрообъект и его субобъекты назначаются явно; назначение одного не добавляет остальные автоматически. Для объединения ГПР нужен доступ к макрообъекту и всем выбранным источникам. Сводная версия с недоступными участниками не открывается целиком; отчёты включают доступные объекты. Проверка действует на сервере и для прямых ссылок/POST-запросов, а не только в списках выбора.


Ограничения планировщика также распространяются на справочники объектов, разделов и работ: списки, фильтры, карточки, редактирование, удаление, состав комплекса, подготовку Excel и подбор источников цены. Проект с неназначенными объектами нельзя удалить целиком, обходя ограничения каскадным удалением. Раздел «Сметы» планировщику недоступен, включая прямые ссылки и выгрузки; пункт меню скрывается.


## Добавление сотрудника и проверка доступа

В списке пользователей основной способ добавления — «Добавить из AD». Найдите сотрудника по ФИО, логину или почте, затем выберите группу доступа. Роль и объекты группы заполняются автоматически и недоступны для отдельного редактирования. Для индивидуальных прав оставьте группу пустой и задайте роль и объекты самостоятельно. Справа отображается доступ после сохранения; для ограниченной роли пустой список объектов явно означает отсутствие доступа к объектам. Этот же порядок применяется к локальным пользователям и изменению существующих пользователей.

## Склад ГСМ

Роль «Склад ГСМ» ведёт дневной приход, расход и остаток топлива. Пункт «Внесение факта → ГСМ · склад» открывает баланс ВЖГ; «ГСМ по объекту» — отдельное направление объектного факта. Это разные регистры: запись складского баланса не создаёт автоматически расход по объекту.

Назначаются только объекты своей компании; доступны ВЖГ, связанные с этими объектами. Без назначений нет доступа к объектам и ВЖГ. Роль не разрешает изменять работы, сотрудников, технику, планы или пользователей. Правила закрытия дней и история изменений распространяются на эту роль; ежедневные задания относятся к направлению ГСМ.

В объектном факте механизация и ГСМ подтверждаются отдельно. «Диспетчер всех направлений» подтверждает четыре направления. Прежние подтверждения механизации, включавшие ГСМ, при обновлении сохраняются также в новом направлении ГСМ. Устаревшая объединённая форма требует обновления перед сохранением.
