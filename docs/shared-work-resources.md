# Общий ресурс для нескольких работ в ГПР и СМГ

В форме назначения выберите «К выбранным работам» и отметьте одну или несколько работ. Поиск учитывает название комплекса, комплексного объекта и работы. «Выбрать найденные» добавляет видимые совпадения к выбору; «Снять выбор» снимает все отметки. Сам комплекс не является новой допустимой привязкой: выбирается работа внутри него либо самостоятельная работа. «Общие ресурсы объекта» остаются отдельным вариантом.

Количество, смены, часы, расход ГСМ и период относятся ко всему назначению. Это один общий ресурс, а не отдельная копия для каждой отмеченной работы. В ГПР карточка появляется под каждой выбранной работой с пометкой «Общий ресурс», раскрываемым списком связей и одним экземпляром в сводке объекта. Из любой связанной работы можно изменить это же назначение. Снятие одной отметки сохраняет ресурс у остальных работ; перенос в общие ресурсы объекта удаляет связи с работами. Удаление назначения снимает его целиком с сохранением закрытой истории СМГ по прежним правилам.

В СМГ тот же выбор доступен в «Ресурсах работ и объекта». Назначенный руководитель может создавать и редактировать назначения; другой руководитель и наблюдатель изменять их не могут. Для СМГ с закрытыми днями привязки начавшихся назначений заблокированы в форме и защищены сервисом. Численность можно менять на открытые дни, закрытые строки сохраняются. Для нового набора работ снимите назначение с оставшихся дней и создайте новое.

## Данные и расчёт

Миграция `planning.0044_work_resource_targets` добавляет таблицу `WorkResourceTarget` для дополнительных связей. Основные поля `WorkResourceAssignment.work/work_item` сохраняются. Старые записи и снимки не переписываются. У новой записи первая допустимая пара хранится в прежних полях, остальные — в `extra_targets`; эффективный набор возвращает `resource_targets.identities/describe`. Ссылки защищены FK PROTECT. Проверяются компания, строительный объект, принадлежность работы комплексу, повторения и допустимость выбранной работы. ГПР дополнительно ограничивает выбор сохранёнными плановыми работами и выбранными позициями состава.

Потребность разворачивается один раз на UUID назначения, без цикла по связанным работам. Техника, экипаж и ГСМ сохраняют прежние формулы. Для общего назначения строки и метаданные дополнены `work_targets`; `target_label` перечисляет связи. Снимки и подтверждения ресурсов, проверка сметчиком и контроль изменений при объединении работ учитывают дополнительные связи. Формат отпечатков старых назначений с одной работой сохранён. При чтении общего назначения следует использовать полный набор связей, а не только legacy-пару `work/work_item`.

Копирование ГПР → СМГ, создание уточнения и новой редакции СМГ сохраняют все связи и фиксированный экипаж. Утверждённый исходный снимок остаётся неизменным. Обычное удаление связанной работы блокируется с понятным сообщением. Администраторская очистка с предварительным просмотром находит связанные планы и по дополнительным работам; изменение и аудит назначения атомарны.

## Проверки

77 целевых тестов прошли: общие количества/часы/экипажи/ГСМ, сохранение и снятие связей, границы компаний и объектов, невыбранные работы, отпечатки, копирование, закрытые дни, права, удаление и откат при ошибке аудита. Два сценария Playwright/Chromium прошли: новый множественный выбор в ГПР и СМГ и прежний полный сценарий редактора ресурсов.

Команды: `manage.py test apps.planning.test_shared_work_resources apps.planning.test_work_resources apps.planning.test_resource_editor apps.planning.test_preparation apps.planning.test_smg_copy apps.works.test_purge apps.works.test_complex_purge`; браузер — `GPR_BROWSER_TESTS=1 SHARED_RESOURCE_BROWSER_TESTS=1 manage.py test apps.planning.test_shared_work_resources_browser apps.planning.test_resource_editor_browser` (при необходимости локальный Bootstrap CSS задаётся `BROWSER_BOOTSTRAP_CSS`). Проверка миграций соответствует моделям.

Расширенный запуск нашёл шесть старых ошибок в `test_daily_schedule` и `test_estimate_legacy_signature`: фикстуры пытаются выполнять действия ресурсами/согласованием от роли планировщика. Все шесть отдельно воспроизведены в копии опубликованной версии `e9081db` до этого изменения; сервисные ограничения ради старых ожиданий не ослаблялись. Исправлено только противоречие HTTP-политики ресурсов с уже существующим правом назначенного руководителя вводить ресурсы; проверка владельца остаётся в сервисе.
