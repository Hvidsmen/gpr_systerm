# Учебные копии портала

Администрирование → Учебные копии. Создайте группу, выберите одного или нескольких активных пользователей своей компании и отдельный порт 8101–8199. Пользователь может участвовать в нескольких группах. Каждая группа получает свою базу SQLite, папки файлов и HTTP-процесс. Учебные группы не меняют обычные группы доступа и роли основного портала.

В списке групп и на странице настройки есть кнопка **«Скопировать ссылку для участников»**. Она доступна администратору, даже если он сам не входит в группу, и копирует постоянный адрес `/accounts/training/<ID группы>/enter/` в основном портале, используя `PORTAL_PUBLIC_URL`. Отправьте эту ссылку назначенным участникам. Ежедневный сброс её не меняет; пересылка другим людям не выдаёт им доступ. Ссылка не содержит одноразового билета или пароля. На внутреннем HTTP-адресе поддерживается копирование без Clipboard API; если браузер запрещает копирование, появляется выделенное поле для ручного копирования.

Участникам появляется задание вида «Учебная копия». Откройте его, нажмите «Открыть учебную копию», затем «Войти в учебную копию». Пароль повторно вводить не нужно. Передаётся одноразовый билет со сроком 60 секунд; пароли Windows не копируются и не передаются. Билет выдаётся только после входа в основной портал и проверки членства в группе.

Внутри все активные участники — администраторы своей учебной группы, с доступом к данным своей компании. Это обычная роль администратора портала, без доступа к Django superuser, настройкам реального сервера, обновлению приложения и внешним интеграциям. Над каждой страницей показан заметный жёлтый баннер и ссылка на основной портал.

## Ежедневный сброс

В **07:00 Europe/Moscow** для каждой включённой группы создаётся новый согласованный SQLite-снимок основной базы. Снимок включает сохранённые данные на момент его создания. Файлы `MEDIA_ROOT` и приватные акты актировки копируются в отдельные папки без общих жёстких ссылок. Файлы и база не являются одной транзакцией: при параллельной загрузке файла в основной портал может понадобиться следующее обновление копии. Символические ссылки и junction в папках файлов не поддерживаются.

Далее в отдельном процессе очищаются сессии, пароли пользователей становятся непригодными для обычного входа, активируются только участники, им назначается ADMIN только в копии. Очередь приглашений отменяется, SMTP-реквизиты и подключения 1С удаляются. Учебный процесс не наследует секреты `.env`, LDAP/SMTP/1С/GitHub. LDAP отключён; отправка писем использует dummy backend. Фоновые обмены и создание новых учебных копий изнутри копии запрещены.

После подготовки прежний учебный HTTP-процесс завершает запросы и останавливается. Меняются ключи, запускается новый процесс, проверяется HTTP health. При неудаче возвращается предыдущая учебная генерация, если она была. Снимок основной базы всегда открывается только для чтения; рабочие базы и файлы не заменяются.

Учебные изменения, загруженные файлы и сессии при успешном сбросе исчезают. Нужен повторный вход через основной портал. В 07:00 начинается обработка, группы обновляются последовательно; фактическое переключение может занять время. Если сервер был выключен, при запуске выполняется один пропущенный сброс, без воспроизведения всех прошедших дней. Ошибка повторяется через пять минут и видна в истории.

Кнопка «Обновить учебную базу сейчас» требует явной отметки об удалении учебных изменений. Сохранение настроек или состава группы тоже ставит обновление в очередь. Обновление релиза или схемы основной базы пересоздаёт копии до запуска их на новой версии кода; обычный перезапуск сервера в том же релизе сохраняет учебные изменения до следующего времени сброса. Отключение группы закрывает вход; удалённый участник теряет доступ по внешнему контрольному файлу, который не редактируется учебной админкой. Обычный вход с сохранёнными паролями и производственными cookies в учебную копию не поддерживается.

## Запуск на сервере

Windows-фоновый сервер (`ops/windows_runtime.py serve`) автоматически запускает диспетчер копий. Пробный процесс при обновлении приложения его не запускает. Дополнительное задание Планировщика Windows не требуется: время 07:00 задано в самом диспетчере явно по Москве и не зависит от часового пояса Windows.

Для пользователей необходимо открыть **только выбранные порты** во внутренней сети. Пример из PowerShell администратора на сервере:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\ops\open-training-ports.ps1 -Ports "8101,8102"
```

Правила ограничены LocalSubnet и профилями Domain/Private. На маршрутизируемой корпоративной сети администратор сети настраивает доступ для необходимых подсетей. Если доступ к порту закрыт, копия может быть готова на сервере, но браузер пользователя её не откроет. Вход открывает тот же адрес сервера, что основной портал, с портом группы. Для HTTPS нужны соответствующие отдельные HTTPS-прокси/порты; встроенные учебные процессы обслуживают HTTP, как текущий внутренний портал.

При обычном `runserver` или отдельном Linux/Waitress-развёртывании запустите под сервисным пользователем, с настройками и окружением основной базы:

```bash
python manage.py run_training_copies
```

Это постоянный процесс, его следует включить в systemd/Supervisor рядом с основным сервером. Он завершает дочерние процессы при штатной остановке; pipe контроля родителя завершает их и при аварийном выходе родителя. Одновременный второй диспетчер блокируется файловой блокировкой. Если сервер обновляет код, перезапустите диспетчер, чтобы копии работали на той же версии схемы и приложения. Самостоятельный запуск `prepare_training_copy` на основной базе запрещён.

Хранилище по умолчанию: `GPR_CONFIG_DIR/.runtime/training`; можно задать отдельный приватный абсолютный путь `GPR_TRAINING_ROOT`. У сервисного пользователя должны быть права на чтение основной БД/файлов и запись сюда. Папка не должна попадать в публичные `media/static`, резервные копии для пользователей или Git. Windows-установка защищает `.runtime` ACL. При собственном пути администратор устанавливает аналогичные права сам.

Настройте `PORTAL_PUBLIC_URL` на адрес основного портала для кнопки возврата; сейчас по умолчанию `http://192.168.70.9:8001/`. В хранилище каждой группы остаются текущая и предыдущая генерация; более старые удаляются после успешного сброса. Планируйте дисковое место примерно на две полные базы и два набора файлов на группу, плюс готовящийся снимок. История обновлений хранится в основной БД, технические ошибки запуска — в приватном `http.log` группы и журнале сервера.

Изменения требуют миграций `accounts.0025` и `planning.0053`. Миграции не создают учебные группы и не меняют рабочие роли; участников выбирает администратор после обновления.
