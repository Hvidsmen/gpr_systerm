# MSSQL для тестового портала

Рабочий и тестовый порталы используют разные базы: `YDS_PORTAL` и `YDS_PORTAL_TEST`. Переключатель `SWITCH_GPR_TEST_TO_MSSQL.cmd` находит отдельное задание `YDS Portal Test`, останавливает только его, создаёт и полностью сверяет `YDS_PORTAL_TEST`, затем меняет `staging.json` и проверяет HTTP-ответ теста. Рабочее задание и `YDS_PORTAL` не изменяются.

Сценарий запускается администратором Windows от `YAMALGAZPROM\dvivanov`. Если тестовое задание ещё работает от `SYSTEM`, сценарий запрашивает пароль Windows и переводит только `YDS Portal Test` на `YAMALGAZPROM\dvivanov`, чтобы использовать встроенную авторизацию SQL Server. Пароль не записывается в файлы и передаётся только планировщику Windows.

Перед переключением сохраняются согласованный снимок SQLite, выгрузка и отчёт сверки. При любой ошибке `staging.json` автоматически возвращается на SQLite и тест запускается снова. После перехода обычные обновления версии теста создают проверенную резервную копию MSSQL и восстанавливают её при неудачной миграции.

Автоматическая полная замена тестовых данных данными рабочего портала временно отключена для MSSQL, чтобы старый SQLite-механизм не мог подменить актуальные данные. Обновление кода тестового портала и сохранение его собственной базы продолжают работать.
