# Смена сотрудника в производственном факте

В разделе «Внесение факта → Производство → Люди» у каждого сотрудника есть выбор **«День» / «Ночь»**. Новая запись по умолчанию дневная. При массовом добавлении выбранная смена применяется ко всем отмеченным людям; затем её можно уточнить отдельно у каждого.

Чтобы исправить уже сохранённый факт, выберите другую смену в строке сотрудника и дождитесь сообщения «Все изменения сохранены». Сохраняется та же запись: должность СМГ, комментарий и связи с выполненными работами остаются. Названия смен видны также в графе связей, сводном отчёте и Excel. При копировании состава предыдущего дня сохраняется его смена.

Один человек не может повторяться в одной дате и смене, в том числе на разных объектах. Если исходную запись или выбранную смену заполняет другой диспетчер, изменение не перезаписывает его ввод. При занятой новой смене выбор возвращается к прежнему, рядом появляется причина. Проверки срока исправления факта, роли, доступных объектов и версии записи сохраняются.

Для смен используются существующие значения `EmployeeActivity.shift`: `1` — день, `2` — ночь. Схема базы и сохранённые числа не меняются. Старые записи с номерами 3–24 показывают прежний номер; их можно сохранить без изменения либо явно переключить на день/ночь. Новые строки производственного факта допускают только день или ночь. Учёт техники сохраняет прежнюю модель смен.

Во время смены сохраняются резервы исходной и новой смены. После сохранения прежний резерв освобождается. Совместное обновление формы не подменяет изменяемую строку старым состоянием. Если другой запрос уже сохраняет форму, переключение ждёт его завершения.

Публикация — в тестовую ветку `codex/staging-portal-20261102`. На тестовом портале: «Проверить обновления» → «Обновить тестовый портал». Рабочая ветка `main` остаётся отдельным выпуском.
