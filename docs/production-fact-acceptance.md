# Приёмочный сценарий блока «Производственный факт»

Этот сценарий обязателен перед утверждением, что пользовательский функционал производственного факта готов. Успешные серверные тесты сами по себе не означают, что интерфейс работает: необходимо пройти весь путь в браузере.

## Тестовый набор данных

Для проверки создаются:

- не менее 250 активных сотрудников, чтобы данные занимали минимум три страницы;
- не менее 250 работ, также минимум на трёх страницах;
- сотрудник без оформленного нахождения в ВЖГ;
- сотрудник, уже внесённый в дневной факт;
- сотрудники дневной и ночной смен;
- работа из СМГ;
- работа без плана;
- самостоятельная работа;
- работа в составе комплекса;
- работа с ненулевым фактом на дальней странице.

Контрольные сотрудники и работы с третьей страницы должны иметь заранее известные ФИО, табельные номера и названия.

## 1. Поиск и добавление работ

Работу с третьей страницы необходимо найти и выбрать каждым способом:

1. Поиск в основной строке работы.
2. Добавление работы вне СМГ.
3. Массовая актировка.
4. Быстрые фильтры работ.
5. Поиск на вкладке «Связи».

Ожидаемый результат:

- поиск выполняется по полному набору, а не по текущей странице;
- выбирается нужная работа;
- повторный выбор не создаёт вторую строку;
- система предлагает открыть существующую строку;
- переход к существующей строке действительно выполняется.

## 2. Поиск и добавление сотрудников

Сотрудника с третьей страницы необходимо найти:

1. В одиночной строке.
2. В массовом окне «Выбрать сотрудников».
3. На вкладке «Связи».
4. В интерфейсе бригад.

В каждом месте проверяется поиск:

- по фамилии;
- по полному ФИО;
- по табельному номеру;
- по должности.

Сотрудник без оформленного ВЖГ должен добавляться. Отсутствие ВЖГ показывается как предупреждение и попадает в сверку, но не блокирует ввод.

## 3. Защита от повторов

Повторно выбрать сотрудника, уже добавленного в ту же дату и смену.

Ожидаемый результат:

- дубликат не создаётся;
- в результате поиска указано, что сотрудник уже добавлен;
- нажатие открывает существующую строку;
- нужная группа раскрывается;
- строка прокручивается в видимую область и подсвечивается;
- кнопка «Отменить изменения» возвращает ошибочную строку в исходное состояние;
- существующая сохранённая строка не изменяется.

Та же проверка выполняется для повторного выбора работы.

## 4. Сохранение

Для работ и сотрудников отдельно проверить:

1. Сохранение кнопкой «Сохранить».
2. Сохранение сочетанием `Ctrl+S`.
3. Сохранение при переходе на следующую вкладку.
4. Повторное сохранение без новых изменений.
5. Сохранение 1, 10 и 15 изменённых строк.
6. Сохранение более 15 строк несколькими небольшими пакетами.
7. Обновление страницы и сверку сохранённых значений.

Ожидаемый результат:

- пустой пакет не отправляется и не вызывает ошибку;
- за один запрос отправляется не более 15 изменённых строк;
- повтор запроса не создаёт дубли;
- сохранённые данные остаются после обновления страницы.

## 5. Ошибки заполнения и навигация

Создать ошибочную строку сотрудника, находясь затем на вкладке «Работы», и попытаться перейти дальше.

Ожидаемый результат:

- ошибка сохранения не запирает пользователя на другой вкладке;
- открывается вкладка с проблемной строкой;
- свёрнутые родительские группы раскрываются;
- форма прокручивается к ошибке;
- строку можно исправить или отменить.

Аналогичная проверка проводится для ошибочной строки работы.

## 6. Слабый и нестабильный интернет

Проверить сценарий при задержке и обрыве соединения:

1. Медленный ответ сервера.
2. Обрыв во время отправки.
3. Повторная отправка после восстановления связи.
4. Двойное нажатие кнопки сохранения.
5. Обновление страницы после ошибки.

Ожидаемый результат:

- заполненные данные остаются в локальном черновике;
- пользователь видит состояние отправки;
- повторная отправка безопасна и не создаёт дубли;
- после восстановления связи можно продолжить с последней заполненной строки;
- фоновые обновления не перезаписывают локальный ввод.

## 7. Полный охват данных за день

Запись с третьей страницы должна учитываться:

- в графе связей;
- в составе бригады;
- в поиске сотрудников и работ;
- в быстрых фильтрах;
- в массовой актировке;
- в дневном сводном отчёте;
- после обновления страницы.

Количество строк в редакторе при этом остаётся ограниченным размером страницы; для расчётов и поиска используется полный набор данных за день.

## Критерий готовности

Функция считается принятой только после успешного прохождения браузерного пути:

> поиск → выбор → изменение → сохранение → переход → обновление страницы → повторный поиск → исправление или отмена

Итог проверки должен отдельно перечислять:

- какие браузерные сценарии пройдены;
- какие серверные тесты пройдены;
- какой объём тестовых данных использован;
- какие сценарии не проверялись.

Формулировка «всё работает» без этого перечня не используется.
