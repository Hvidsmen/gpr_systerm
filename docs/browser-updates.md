# Обновление портала из браузера

Администратор открывает «Обновление приложения» в боковом меню и нажимает «Обновить приложение». Это ставит запрос штатному Windows-supervisor через существующий протокол `.runtime/update.request`. Браузер не запускает PowerShell, не требует системных привилегий пользователя браузера и не выполняет переданные пользователем команды.

Источник фиксирован: последняя версия `main` репозитория `Hvidsmen/gpr_systerm`. Сохраняется существующий порядок: подготовка новой версии и окружения, проверка приложения, остановка HTTP-процесса, резервная копия базы, миграции, пробный запуск, запуск общедоступного портала, проверка доступности. Обычные отказы обновления обслуживаются штатным восстановлением предыдущей версии и базы; исключительное состояние `recovery_required` требует восстановления на сервере.

Вкладку можно закрыть после принятия запроса. Состояние последнего браузерного запроса хранится вне обновляемой базы, а результат читает `.runtime/results/<id>`. Административная страница автоматически проверяет этапы и повторяет попытки подключения во время перезапуска. «ГОТОВО» появляется по успешному результату фонового обработчика после восстановления HTTP-доступа. Если версия уже актуальна, отображается отдельное сообщение. Результат чужой компании, секреты, полные служебные JSON и пути резервных копий не отдаются клиенту.

Права ADMIN проверяются в страницах, JSON-статусе и сервисе постановки запроса. Запуск — только POST с CSRF. Повторные браузерные запросы и запуск командой во время активного обновления блокируются. Запрос фиксируется в аудите; идентификатор, инициатор и компания сохраняются в `.runtime/web-update.json`.

Требуется установленный и запущенный фоновый портал Windows с доступом его учётной записи к `.runtime`. После публикации этой функции один раз обновите сервер прежней командой `git pull --ff-only origin main` и `UPDATE_GPR_BACKGROUND.cmd`, чтобы новая административная страница появилась в работающей версии. Дальнейшие обновления запускаются из браузера. Перенастраивать Планировщик не требуется.

## Статус-бар

На странице обновления отображается полоса завершённых этапов: проверка версии, скачивание, зависимости, проверка приложения, остановка, резервная копия, миграции, пробный запуск, запуск, проверка доступности. Индикатор отражает этапы, а не долю скачанных байтов или оставшееся время. Во время последнего этапа прогресс остаётся ниже 100%; 100% и зелёное «ГОТОВО» появляются только после успешного результата.

Администратор видит компактный статус-бар и в других разделах портала. Он скрыт при отсутствии обновления, показывается во время процесса и после его завершения; завершённое уведомление можно скрыть. При перезапуске браузер сохраняет последнее положение полосы и ждёт восстановления HTTP. Новая страница показывает недавний результат в течение пяти минут, без вывода служебных путей.
