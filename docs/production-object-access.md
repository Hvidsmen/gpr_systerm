# Производство: доступ к объектам и ежедневные задания

Для ролей «Диспетчер по производству» (`DISPATCHER`) и «Диспетчер всех направлений» (`ALL_FACT_DISPATCHER`) ежедневные задания отделены от возможности изменять производственный факт.

В карточке пользователя (Администрирование → Пользователи → Настроить доступ), при добавлении из AD и в группе доступа есть два списка:

- **Основные объекты · с ежедневными заданиями** — диспетчер видит и меняет факт, получает ежедневное задание за предыдущий день.
- **Производство: дополнительные объекты без ежедневных заданий** — диспетчер также видит и меняет факт, сотрудников, связи, причины и документы актировки. Автоматические ежедневные задания по этим объектам не создаются.

Пример: основные объекты — **КТП-1**, дополнительные — **КТП-2**. Диспетчер может просматривать и изменять производство по обоим КТП, а ежедневное задание получает только по КТП-1. Основные объекты уже доступны; повторять их во втором списке не нужно. Если основных объектов нет, но дополнительные выбраны, ввод на них доступен без автоматических заданий.

При выборе группы оба списка и роль наследуются автоматически. Редактировать их нужно в группе либо снять группу и назначить индивидуальные права. Изменение дополнительных объектов не создаёт и не отменяет подписку на задания. Чтобы прекратить ежедневные задания по объекту и сохранить ввод, перенесите его из основных в дополнительные. Прежние незавершённые задания отменяются по прежним правилам снятия основного назначения.

По дополнительному объекту работает обычный производственный ввод: автосохранение, совместная работа, резервирование, смены, очистка работ, очередь связей при нестабильном интернете, копирование предыдущего дня, актировка и файлы. Остаются прежние ограничения роли, компании, окна ввода, редакций и резервов. Редактирование вне разрешённых объектов и объектов другой компании закрыто. Доступ к дополнительным объектам не расширяет остальные роли, редактирование планов и доступ к ВЖГ.

Сводный отчёт, план/факт СМГ, Excel и история доступны по обоим спискам. Создание заданий продолжает использовать только `assigned_objects`; объединение двух списков применяется явно внутри производства (`production_scope=True`). Другие разделы сохраняют прежнюю область доступа.

Миграция `accounts.0028_production_additional_objects` переименовывает прежние связи `production_view_objects` в `production_additional_objects`. Опубликованная миграция 0027 не меняется. Выбранные у пользователей и групп объекты сохраняются и теперь разрешают ввод без ежедневных заданий. Основные назначения, факты и задания не пересчитываются. Создание отдельной базы пользователей с сохранением объектов переносит оба вида назначений; без объектов оба вида не переносятся.

Изменения публикуются в тестовую ветку `codex/staging-portal-20261102`. Установка на сервер — через обновление тестового портала; рабочий `main` выпускается отдельно после проверки.

Проверки охватывают изменение факта и связей на дополнительном объекте, оба протокола связей, резервирование, присутствие, отсутствие автоматических заданий, снятие основных назначений с сохранением ввода, ограничения компании и роли, наследование групп, отзыв AD-членства, сохранение назначений при миграции и переносе отдельной базы пользователей. Браузерный сценарий меняет объём и связи, перезагружает страницу, проверяет сохранённый результат и мобильную раскладку.
