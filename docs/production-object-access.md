# Разделение просмотра и заполнения производства

Для ролей «Диспетчер по производству» (`DISPATCHER`) и «Диспетчер всех направлений» (`ALL_FACT_DISPATCHER`) область просмотра производственного факта отделена от ввода и подписки на ежедневные задания.

В карточке пользователя (Администрирование → Пользователи → Настроить доступ), при добавлении из AD и в группе доступа есть два списка:

- **Объекты для заполнения / работы** — прежние назначения. Диспетчер видит объект, заполняет своё направление и получает ежедневное задание за предыдущий день.
- **Производство: дополнительные объекты для просмотра** — только просмотр факта за день, связей, сводного отчёта, план/факта СМГ, Excel, актов и истории производства. Ввод и задания этим списком не выдаются. Объекты из первого списка уже видны; дублировать их не нужно.

Пример: для заполнения выбрать **КТП-1**, дополнительно для просмотра — **КТП-2**. Диспетчер видит оба объекта, меняет данные и получает задания только по КТП-1. На КТП-2 отображается «Только просмотр», видны сохранённые данные других авторов; форма не запускает автосохранение и резервирование.

При выборе группы оба списка и роль наследуются автоматически. Редактировать их нужно в группе либо снять группу и назначить индивидуальные права. Изменение дополнительных объектов просмотра не отменяет и не создаёт задания. Изменение объектов заполнения сохраняет прежнюю логику отмены старых задач и создания новых. Если объекты заполнения пусты, но есть объекты просмотра, диспетчер может смотреть их без ежедневных заданий.

Ограничение действует на сервере: прямые POST-запросы на факт, связи, копирование предыдущего дня, резервирование, причины и документы актировки проверяют прежние назначения для ввода. Права роли, компания, точные назначения субобъектов, окно ввода и проверки совместной работы сохраняются. Родительский объект не выдаёт доступ ко всем его субобъектам автоматически. Дополнительный просмотр не выдаёт доступ к редактированию планов, кадровому разделу, ВЖГ и чужим заданиям. Для остальных ролей эта дополнительная настройка не расширяет права.

Миграция `accounts.0027_accessgroup_production_view_objects_and_more` добавляет две пустые связи многие-ко-многим. Существующие назначения, факты и задания не пересчитываются; после обновления прежний доступ сохраняется. Новые области просмотра администратор выбирает явно. Создание отдельной базы пользователей с сохранением объектов переносит оба вида назначений; без объектов оба вида не переносятся.

Изменения выпускаются в тестовую ветку `codex/staging-portal-20261102`. Установка на сервер — через обновление тестового портала; рабочий `main` выпускается отдельно после проверки.

Проверка реализации: 162 регрессионных серверных теста и отдельные 16 проверок окончательного интерфейса, прав и инструкций прошли. Chromium проверяет редактирование двух областей, наследование и восстановление выбора группы, запрет фоновых POST в просмотре, доступность ввода на назначенном объекте и мобильную раскладку. Проверен прежний сценарий добавления из AD и настройки локального пользователя.

В дополнительной старой группе `apps.projects.test_assignment_scope` остаются два прежних ожидания 404 вместо фактически возвращаемого 403. Они воспроизведены на родительском коммите `fd694101982798e94f40230ea5d577c9c4feca93`; данное изменение их не меняет.
