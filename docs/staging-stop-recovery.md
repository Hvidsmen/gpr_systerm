# Восстановление обновления теста после тайм-аута остановки

Диагностический признак: `Acceptance web update failed` → `stop_http(child)` → `subprocess.TimeoutExpired ... timed out after 115 seconds`. Такой запуск остановился до применения новой версии. Старый запущенный обработчик не сможет установить исправление своей остановки через тот же путь.

## Обычные последующие обновления

`stop_http` сначала закрывает вход дочернего HTTP-процесса и даёт ему прежние 115 секунд. Если процесс остаётся жив, завершает только объект `Popen`, созданный тестовым обработчиком; после дополнительного ограниченного ожидания допускается `kill` того же процесса. Без подтверждённого выхода установка не продолжается. Поиск и массовое завершение `python.exe` не используются. Рабочий обновлятор не меняется.

## Однократное восстановление старой установки

Используйте `ops/repair-staging.ps1` из проверенного точного SHA исправления в PowerShell администратора на сервере. Параметр `-Revision` принимает только полный SHA. Папка определяется из единственного действия задачи `YDS Portal Test`, поэтому запуск возможен из любой текущей папки.

Сценарий:

1. Проверяет имя/каталог/интерпретатор/аргументы задачи и признак отдельного теста. Отказывается работать с рабочей конфигурацией, выключенной задачей, уже идущим обновлением и маркерами восстановления базы.
2. Загружает исходники выбранного SHA через проверяемый bootstrap: Git либо прямые файлы GitHub с проверкой хешей. Во время загрузки тест продолжает работать. Ручное скачивание архива не требуется; проверенный исходник временно упаковывается локально для штатного механизма установки.
3. Временно отключает автоматический перезапуск только `YDS Portal Test`, запрашивает остановку, при необходимости завершает эту задачу и проверяет освобождение её порта. Дополнительно штатная установка требует эксклюзивной блокировки тестового HTTP-процесса.
4. Применяет выбранную версию через обычные резервное копирование, зависимости, проверки, миграции и переключение тестовой конфигурации. Данные, документы, секрет теста и учётные записи сохраняются. Рабочие задачи, файлы и база не меняются.
5. Включает и запускает ту же задачу теста, ждёт правильные HTTP-заголовки окружения/версии и подтверждает успешный результат. Благодаря полному перезапуску задачи новый обработчик остановки загружается и для будущих обновлений.

Если применение завершилось ошибкой и штатное восстановление не потребовало ручного вмешательства, выбранная конфигурация теста запускается снова. При маркере восстановления база не запускается автоматически. Уже существующие неизменяемые каталоги релизов не переписываются и не удаляются; незавершённый каталог оставляется для проверки. Временный локальный архив удаляется, проверенный исходник остаётся для повторной диагностики.

Журналы находятся именно в папке, указанной `WorkingDirectory` задачи теста: `.runtime/server.log`, `.runtime/prepare.log`, `.runtime/repair.log`. Для корректной кириллицы в Windows PowerShell используйте `Get-Content -Encoding UTF8`. Передавать `.env`, `secret.key` и саму базу для диагностики не требуется.

## Проверки

Есть реальные проверки зависших дочерних процессов, включая игнорирование EOF и (на Unix) SIGTERM, проверки сохранения блокировки до выхода, отказов восстановления и подтверждения успеха только после health check. PowerShell-проверки моделируют задачу/порт/ошибки и контролируют, что операции обращаются только к `YDS Portal Test`. В Windows CI добавлены синтаксис/проверки сценария и проверки дочернего процесса на Python 3.13. Опциональный интеграционный прогон `STAGING_BROWSER_TESTS=1 STAGING_RELEASE_TESTS=1 STAGING_REPAIR_INSTALL_TESTS=1` выполняет настоящий перенос тестовой версии со свежим venv, миграциями, статикой и проверкой сохранённых данных.
