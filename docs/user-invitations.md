# Приглашения пользователей

Администратор компании открывает «Администрирование → Пользователи».
В строке сотрудника нажмите «Пригласить». Для нескольких сотрудников отметьте
строки и нажмите «Отправить приглашения». Флажок «Все найденные по фильтру»
включает все страницы текущего фильтра, максимум 5000 получателей за раз.

Сначала открывается проверка адресов, настоящих логинов Windows, ролей и текста
письма. Проверьте список и подтвердите отправку. Каждому сотруднику уходит отдельное
письмо: адрес портала, его логин, роль, пояснение про пароль Windows, четыре шага
входа и ссылка на инструкцию по роли. Сам пароль Windows нигде не сохраняется
и в письмо не вставляется. Приглашения не меняют права и не создают аккаунты.

Приглашения рассчитаны на корпоративные учётные записи AD. Локальные,
отключённые и архивные записи, записи без роли, корректного email или
подтверждённого логина Windows показываются с объяснением и не отправляются.
Для старых AD-аккаунтов логин и отсутствующий email уточняются через имеющееся
подключение к AD. Служебный идентификатор вида ad:GUID не используется для входа.

## Исходящая почта

В разделе пользователей откройте «Исходящая почта». Укажите выданные провайдером
SMTP-сервер, порт, SSL/TLS или STARTTLS, логин почтового ящика, пароль,
адрес отправителя и адрес портала. IMAP-сервер для отправки не подходит.
Нажмите «Сохранить и проверить SMTP»: проверяются подключение и авторизация,
письма при этом не отправляются.

Для LanCloud в новой форме при отсутствии SMTP в окружении предлагаются
проверенные по [руководству провайдера](https://kb.lancloud.ru/content/cloudexchange/pop3-imap4-smtp-setup/)
значения: smtp.lancloud.ru, порт 587, STARTTLS. Логин — полный адрес почтового
ящика; для текущего портала это site@yamaldorstroy.ru. Пароль введите в форме
и сохраните. Также провайдер поддерживает порт 465 с SSL/TLS.
На тарифах Standard и Enterprise SMTP по умолчанию может быть отключён:
в панели cp.lancloud.ru откройте CloudExchange → Почтовые ящики → свойства
нужного ящика → Функции и включите SMTP Submit Allowed.
Начальное заполнение формы само не сохраняет настройки и не отправляет письма.
Адрес портала по умолчанию — http://192.168.70.9:8001/.

Пароль почтового ящика хранится в базе зашифрованным с использованием SECRET_KEY
сервера и компании. Пустое поле сохраняет прежний пароль; в интерфейс и аудит
он не возвращается. При замене SECRET_KEY введите пароль почты заново.
Не добавляйте пароль в репозиторий. Вместо формы можно настроить EMAIL_HOST,
EMAIL_PORT, EMAIL_HOST_USER, EMAIL_HOST_PASSWORD, DEFAULT_FROM_EMAIL,
EMAIL_USE_TLS, EMAIL_USE_SSL и PORTAL_PUBLIC_URL в окружении сервера.
Сохранённые настройки компании имеют приоритет над окружением.

## Очередь и история

Подтверждение сохраняет очередь в базе; страницу можно закрыть. История доступна
через «Приглашения». Статусы обновляются автоматически. «Передано почтовому
серверу» означает приём SMTP-сервером, а не доставку в папку входящих и не прочтение.
Если изменились роль, email, имя, логин, активность или адрес портала,
подготовьте новый предпросмотр: старые данные не отправляются.

Повторное подтверждение того же списка и «Продолжить отправку очереди» не
повторяют уже переданные письма. При ошибке авторизации очередь приостанавливается:
исправьте настройки и продолжите её. При недоступности сервера повторное
подключение выполняется с задержкой. После обрыва связи во время отправки
результат требует проверки: проверьте почту получателя перед новым приглашением.

Windows supervisor запускает резервную обработку очереди каждые 30 секунд.
Для Linux настройте периодический запуск команды, а для разовой обработки:

```sh
python manage.py process_invitations --limit 100
```

Встроенный фоновый обработчик запускается после подтверждения; постоянный
обработчик нужен для восстановления очереди после перезапуска процесса.
INVITATION_ASYNC_ENABLED=False отключает только встроенный поток.
Все страницы и отправки ограничены администратором и его компанией.
