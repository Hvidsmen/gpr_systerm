# Согласование планов ГПР и СМГ

Администратор назначает роли через **Пользователи → Роль и объекты** либо через группу доступа. Для новой ветки используется отдельная роль **Служба СБО** (`SBO_HEAD`). Она не заменяет Службу безопасности.

## Маршрут

1. Планировщик готовит работы и передаёт план руководителю и сметчику.
2. Руководитель определяет ресурсы; сметчик проверяет работы и цены.
3. После проверки сметчика и готовности ресурсов руководитель отправляет план на согласование.
4. Пять профильных служб согласуют независимо, в любом порядке.
5. Генеральный директор утверждает план только после подтверждений всех служб.

| Служба | Роль | Решение |
|---|---|---|
| Производство | `PRODUCTION_HEAD` | Работы и состав комплексов |
| Кадровая служба | `HR_HEAD` | Должности |
| Техническая служба | `TECH_HEAD` | Техника и ГСМ |
| Служба безопасности | `SECURITY_HEAD` | Согласование СБ |
| Служба СБО | `SBO_HEAD` | Согласование СБО |

Решение каждой службы обязательно. СБО может согласовать первой, одновременно с другими службами: их решений ждать не нужно. Одного подтверждения раздела в текущем раунде достаточно.

Администратор может принимать решения за каждую службу своей компании. В истории сохраняются его фактическая роль `ADMIN`, конкретный раздел, имя, дата и комментарий. Генеральный директор получает задание, когда готовы все обязательные подтверждения. Это ограничение действует и при прямом запросе к серверу.

## Задания и права

Каждой службе создаётся отдельное задание. Если в компании ровно один активный пользователь с соответствующей ролью, задание назначается ему. Иначе оно доступно очереди этой роли. Пользователи других компаний не видят план и не могут принять решение.

В разделе **Согласование планов** отображаются отдельные столбцы служб, включая СБО. После своего согласования пользователь службы больше не видит план среди ожидающих его решения. Состояние также видно в карточке плана.

Служба СБО может согласовать свой раздел или вернуть весь план на доработку с обязательным комментарием. Она не может согласовать чужой раздел или утвердить весь план.

## Доработка и история

Возврат ГПР переводит версию на доработку, возврат СМГ — в черновик. После исправления нужна актуальная проверка сметчика и новая отправка. В новом раунде все службы, включая СБО, подтверждают план заново. Предыдущие решения и снимки остаются в истории.

После отправки состав плана фиксируется. Последующие изменения справочника не подменяют согласованный снимок. Месячные уточнения сохраняют ссылку на конкретный утверждённый раунд базы.

Генеральный директор или администратор может завершить утверждённый ГПР. Завершённый план не редактируется. Для согласованного СМГ следующим действием остаётся применение в оперативном планировании.

## Обновление

Выполните штатное обновление портала с миграциями:

```powershell
git pull origin main
python manage.py migrate
python manage.py check
```

Миграция `accounts/0017_sbo_role` добавляет роль без изменения назначенных пользователям ролей. Назначьте её ответственным сотрудникам или группе доступа.

Миграция `planning/0049_sbo_approval` добавляет задания СБО в текущие открытые раунды. Если план уже ожидал генерального директора, его задание откладывается до согласования СБО и затем открывается снова. Остальные решения текущего раунда сохраняются.

Уже утверждённые, применённые, архивные и завершённые планы сохраняют статус, снимки и историю. Согласование СБО задним числом не создаётся. Новые редакции проходят полный маршрут.
