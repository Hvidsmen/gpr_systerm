# Согласование плана ГПР

Администратор назначает роли в разделе **Пользователи → Роль и объекты**.
Миграции добавляют новые роли, сохраняя назначенные ранее роли пользователей.

| Роль | Решение |
|---|---|
| Планировщик (`PLANNER`), администратор (`ADMIN`) | Готовят черновик и отправляют на согласование |
| Руководитель производства (`PRODUCTION_HEAD`) | Согласует работы, включая подработы |
| Руководитель кадровой службы (`HR_HEAD`) | Согласует людей |
| Руководитель технической службы (`TECH_HEAD`) | Согласует технику и ГСМ одним решением |
| Генеральный директор (`CEO`) | Утверждает весь план после трёх служб, возвращает на доработку, завершает |

Службы согласуют независимо, в любом порядке. После отправки весь состав
версии фиксируется; изменение работ, ресурсов, нормативов и месячных строк
заблокировано. Каждый руководитель отвечает только за своё согласование.
Одного решения по каждому разделу в раунде достаточно.

В меню **Согласование планов** руководитель службы видит отправленные версии,
по которым его решение ещё не принято. Генеральный директор видит версии
после всех трёх согласований, а также утверждённые версии для завершения или
возврата. Планировщик, администратор и общий руководитель могут просматривать
состояние согласования без права принятия решений за службы.

## Доработка и завершение

Любой из трёх руководителей может вернуть всю отправленную версию на доработку,
указав обязательную причину, в том числе после своего согласования раздела.
После окончательного утверждения вернуть её может только генеральный директор.
Генеральный директор также может вернуть версию, поступившую ему после служб.

Планировщик исправляет ту же версию. Повторная отправка создаёт новый раунд:
все три согласования необходимо получить заново. Предыдущие снимки плана,
решения, имена участников, причины и даты остаются в истории версии.
Удаление пользователя сохраняет его имя в истории решения.

Месячные версии привязаны к конкретному утверждённому раунду базы. Возврат
базы и её повторное утверждение не подменяют базу уже созданных уточнений.
Для новых уточнений используется актуальная утверждённая база.

Генеральный директор завершает только утверждённый план. Статус **Завершён**
окончателен: содержание и статус больше не изменяются. Нужные новые месячные
редакции создаются отдельными версиями с собственным согласованием.

Историю нельзя удалить отдельно. Администратор сохраняет ранее предусмотренную
возможность удалить рабочее пространство целиком с явным подтверждением
удаления его истории; производственные факты при этом остаются.

## Обновление

```powershell
git pull origin main
python manage.py migrate
python manage.py check
```

Перезапустите сервер. Назначьте пользователям четыре новые роли.
Старые утверждённые и завершённые планы сохраняют свой статус: миграция
помечает их прежнее утверждение, не придумывая согласований служб задним числом.
Планы, уже находившиеся на согласовании, проходят новый маршрут с трёх служб.
Общий руководитель (`MANAGER`) продолжает согласовать нижние планы работ,
но для глобального плана его роль нужно заменить соответствующей новой ролью.
