# Новая база с пользователями и правами

Операция создаёт новый файл `data/users-only-<дата-время>.sqlite3` и переключает на него фоновый портал. Старый файл остаётся на месте; дополнительно создаётся согласованная резервная копия SQLite в защищённой `.runtime/backups`. До переключения проверяются связи и целостность новой базы. Существующий файл никогда не используется как назначение создания.

Переносятся компании пользователей, пользователи (включая хеши локальных паролей, AD GUID, источник входа, признаки активности, администратора и staff), роли, группы доступа, соответствия группам AD, стандартные группы Django и индивидуальные разрешения. `.env`, адрес LDAP и пароль подключения не меняются. Пользователю нужно войти заново: сессии и режим входа от имени пользователя не копируются.

Не переносятся работы, техника, сотрудники, экипажи, сметы, планы, факты, задания, журналы и личные настройки отчётов. Служебные таблицы схемы, типов содержимого и разрешений сохраняются для работы Django.

Два режима назначения объектов (режим обязателен, автоматического выбора нет):

- `keep` — сохранить справочник проектов/строительных объектов и назначения пользователям/группам, без разделов, работ и планов.
- `clear` — оставить проекты/объекты пустыми и очистить только назначения на объекты. Роли, группы и разрешения сохраняются; назначить объекты нужно после заполнения новой базы.

Сначала обновить приложение и дождаться `ГОТОВО`:

```powershell
cd "C:\Users\dvivanov\Desktop\gpr_system"
git pull --ff-only origin main
.\UPDATE_GPR_BACKGROUND.cmd
```

Затем **в PowerShell от имени администратора** выполнить одну выбранную команду:

```powershell
.\NEW_GPR_DATABASE.cmd keep
```

либо, если нужен полностью пустой справочник объектов:

```powershell
.\NEW_GPR_DATABASE.cmd clear
```

Во время копирования и переключения портал кратковременно останавливается; задания автозапуска и обновления временно отключаются. После завершения прежние настройки заданий восстанавливаются, портал запускается и проверяется страница входа. При ошибке подготовки переключение не выполняется и запускается прежняя база. Прерванное переключение использует штатный журнал восстановления. Повторный запуск создаёт ещё одну новую базу с новым именем, а не очищает текущий файл.

Путь выбранного файла показывается в конце. Подробности ошибок — `.runtime/control.log` и `.runtime/commands.log`. Возврат к исходному файлу: `SWITCH_GPR_DATABASE.cmd "<путь к прежней базе>"`. Это возвращает состояние старой базы, без записей, сделанных в новой после переключения.

Для подготовки без переключения есть служебная команда текущей версии приложения:

```text
python manage.py create_users_database --source <резервная-копия.sqlite3> --target <новый-файл.sqlite3> --object-access keep|clear
```

Она читает источник без записи, проверяет одинаковую историю миграций и создаёт новую схему перед переносом. Для работающего Windows-сервера используйте оболочку `NEW_GPR_DATABASE.cmd`, которая останавливает фоновые процессы и создаёт резервную копию до переноса.
