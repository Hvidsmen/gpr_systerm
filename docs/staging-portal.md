# Постоянный тестовый портал для приёмки

Рабочий портал остаётся на прежнем адресе `http://192.168.70.9:8001/`. Тест устанавливается в отдельную папку и по умолчанию слушает порт 8002. Его устанавливают из отдельной ветки/архива, без слияния в `main` и без обновления работающего портала. Наличие этой инструкции не означает, что тест уже установлен на вашем сервере.

Вход первоначально разрешён одному владельцу. Его логин однозначно сопоставляется с активным пользователем и компанией в снимке рабочей базы. Для теста задаётся **свой новый пароль**; пароль Windows не нужен. Остальные учётные записи остаются в снимке для проверки ролей через «Работать как пользователь», но самостоятельно войти на тест не могут, даже если им задать пароль через карточку пользователя. В будущем состав проверяющих можно расширить отдельным изменением правил доступа.

## Что разделено

У теста свои база SQLite, загруженные файлы, приватные акты, секретный ключ, cookie сессии/CSRF, статические файлы, зависимости Python, журналы, резервные копии и задание Windows `YDS Portal Test`. Cookie имеют уникальные имена: одновременный вход на одном IP с портами 8001 и 8002 не завершает рабочую сессию.

Тестовый сервер не запускает менеджер учебных копий и фоновые обмены. LDAP отключён. Подключения 1С и сохранённые SMTP-реквизиты удаляются **только из снимка**, очередь приглашений отменяется, копии сессий и пароли очищаются. Реальная отправка почты заменена dummy backend, запуск почтового потока отключён. Регистрация, подключение AD/1С, приглашения, учебные копии и обновлятор рабочего портала дополнительно заблокированы на уровне middleware. Переключение ролей владельцем разрешено.

Тест не сбрасывается в 07:00. Его данные сохраняются после перезапуска компьютера и при обновлении кода теста. Базу с теста в прод не переносят.

## Первая установка одной командой, без архива

В PowerShell **от имени администратора на сервере** выполните следующий блок. Вместо `SHA_ИЗ_PR` укажите полный SHA подготовленной версии из pull request, а не `main`:

```powershell
$revision = 'SHA_ИЗ_PR'
$installer = Join-Path $env:TEMP 'install-yds-test.ps1'
Invoke-WebRequest -UseBasicParsing -Uri "https://raw.githubusercontent.com/Hvidsmen/gpr_systerm/$revision/ops/bootstrap-staging.ps1" -OutFile $installer
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $installer -Revision $revision
```

Вручную скачивать и распаковывать ZIP не нужно. Скрипт получает **точный коммит** в отдельную папку. Если установлен Git, используется отдельный checkout; без Git файлы загружаются напрямую с GitHub и сверяются с Git blob SHA-1, включая бинарные документы. Архивы не используются ни в одном варианте. Имена файлов, ссылки, полнота дерева и отсутствие пересечения с рабочими путями проверяются до установки. Незавершённая загрузка удаляет только созданную для неё временную папку.

Папка работающего портала по возможности определяется из задания `YDS Portal` (только чтение). Если это не удалось, скрипт спросит её. По умолчанию рядом создаётся `YDS-Test`. Существующая папка или уже установленный тест не перезаписываются. Для другого размещения передайте `-Root` и `-ProductionRoot` в команду запуска.

Далее установщик спросит ваш логин и новый **отдельный тестовый пароль** длиной не менее 12 символов. Пароль вводится скрыто; он не попадает в аргументы команд или открытый файл. Рабочие `.env`, ключи и виртуальное окружение не копируются.

После успешной установки адрес теста по умолчанию — `http://192.168.70.9:8002/`. Над каждой страницей должен появиться баннер «ТЕСТОВЫЙ ПОРТАЛ», номер версии и ссылка на рабочий портал. До запуска установщика на вашем сервере этот адрес нельзя считать уже работающим.

Для явного выбора параметров:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $installer -Revision $revision `
  -Root C:\YDS-Test -ProductionRoot C:\YDS-Prod -OwnerLogin YOUR_LOGIN -Port 8002 -Hosts 192.168.70.9
```

При необходимости можно по-прежнему распаковать ZIP точного коммита в отдельную папку и запустить `INSTALL_GPR_TEST.cmd`; это дополнительный способ, а не требование.

Нужна уже установленная Windows-версия с `.runtime/installed.json` и `.runtime/current.json`. Установщик использует базовый интерпретатор установленного Python, но создаёт собственное окружение теста. Зависимости фиксированы в `requirements.staging.lock` (включая основной lock-файл). Если Python недоступен, передайте `-PythonExecutable`. Если приватные акты лежат по нестандартному `ACTUATION_FILES_ROOT`, передайте их папку параметром `-ActuationRoot`.

Снимок БД делается через SQLite Backup API с источником `mode=ro` и проверкой целостности. Рабочая БД не мигрируется и не заменяется. Документы копируются отдельными файлами. Они и БД не образуют единую транзакцию: загрузка нового документа одновременно с копированием может потребовать повторного копирования при следующей подготовке снимка. Ссылки, junction и совмещение рабочих/тестовых путей запрещены. Нужны место для полной копии данных и права чтения источника.

Повторная установка поверх существующего теста отказывается перезаписывать данные. Если подготовка не завершилась, готовая конфигурация не публикуется; журнал — `.runtime/prepare.log`. Установщик не останавливает и не перерегистрирует задания `YDS Portal` / `YDS Portal Update`. Он создаёт только `YDS Portal Test` и правило `YDS-Portal-Test` для выбранного порта во внутренней подсети, профили Domain/Private. Это программная изоляция двух установок на одном сервере; отдельная виртуальная машина даст дополнительную изоляцию ресурсов и прав ОС.

## Управление только тестом

Из папки теста, PowerShell администратора:

```powershell
.\ops\control-staging.ps1 -Action Status
.\ops\control-staging.ps1 -Action Stop
.\ops\control-staging.ps1 -Action Start
```

Либо `CONTROL_GPR_TEST.cmd -Action Status`. Остановка ждёт завершения запросов. При превышении времени обновление не начинается. Скрипт проверяет, что задание теста принадлежит выбранной папке. Рабочие задания не затрагиваются.

## Обновление теста до конкретного кандидата

Скачайте ZIP нового проверяемого коммита. Внутреннее имя корня архива GitHub должно соответствовать указанному SHA; архив ветки `main.zip` не принимается.

```powershell
.\ops\control-staging.ps1 -Action Update -Archive C:\Downloads\candidate.zip -Revision EXACT_40_CHARACTER_COMMIT_SHA
```

Скрипт останавливает **только тест**. Новый код и собственное окружение Python готовятся в `.runtime/releases/<SHA>`. Перед миграциями сохраняются снимок тестовой БД и прежняя конфигурация. Выполняются `check`, миграции и `collectstatic`; затем переключается указатель версии и запускается тестовый сервер. Рабочие база, файлы, код и задачи не обновляются.

При сбое подготовки миграций тестовая база восстанавливается из снимка, пока HTTP-сервер остановлен и удерживается блокировка. Старая конфигурация остаётся выбранной. Проверьте `.runtime/prepare.log`, затем запустите тест отдельно. После возобновления пользовательского ввода автоматически восстанавливать БД нельзя: новые данные требуют отдельного решения.

## Выпуск в прод

Приёмка на тесте не означает разрешения на выпуск. Изменения остаются в отдельной ветке и pull request. Слияние в `main` и выпуск рабочей версии требуют подтверждения конкретного релиза пользователем.

У существующего рабочего установщика есть задание `YDS Portal Update`, запускающее проверку `main` при старте компьютера. Этот установщик теста его не меняет. До перехода на утверждённые релизы нужно отдельно согласовать и выполнить изменение политики обновлений рабочего сервера. Нельзя считать его уже отключённым из-за создания теста.
