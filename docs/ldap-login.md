# Вход через Active Directory

Реализован отдельный способ входа «Корпоративная учетная запись AD». По согласованной конфигурации используется обычный LDAP Simple Bind, порт 389, без StartTLS и LDAPS. Основной сервер 192.168.70.12, резервный 192.168.70.13; переход на резервный выполняется при сбое подключения/LDAP, отрицательный ответ о пароле не заменяется локальной проверкой.

## Настройка сервера

1. Установить зависимости: `python -m pip install -r requirements.txt`.
2. В локальном `.env` рядом с manage.py задать:

```dotenv
LDAP_ENABLED=true
LDAP_SERVERS=192.168.70.12,192.168.70.13
LDAP_PORT=389
LDAP_DOMAIN=yamalgazprom.local
LDAP_BIND_USER=portal-ldap@yamalgazprom.local
LDAP_BIND_PASSWORD=
LDAP_BASE_DN=OU=Yamaldorstroy,DC=yamalgazprom,DC=local
LDAP_TIMEOUT=5
```

В `LDAP_BIND_PASSWORD` вписать служебный пароль непосредственно на сервере. Если он содержит `#`, кавычки или пробелы, корректно заключить значение в кавычки по синтаксису python-dotenv. Пароль не передавать аргументом команды и не добавлять в Git. В репозитории хранится только пустой пример.

3. Выполнить миграции или запустить START_GPR. Для раздельной проверки доступности: `python manage.py check_ldap`. Команда проверяет служебную привязку и OU на обоих серверах, не показывает пароль и не изменяет AD. Для реальной проверки входа требуется отдельная пользовательская учетная запись.
4. На странице входа выбрать корпоративный способ. Поддерживаются короткий sAMAccountName, `логин@yamalgazprom.local` и `YAMALGAZPROM\логин`. Поиск ограничен указанным OU и вложенными OU; отключенные в AD записи исключены. Учетная запись проверяется отдельным bind под найденным DN пользователя. Пароли пользователей не сохраняются.
5. После первого успешного входа появляется ожидающая назначения карточка. Суперпользователь в Django-админке назначает компанию, роль и при необходимости объекты. Группы AD, права администратора AD и названия должностей автоматически не дают роли в ГПР. LDAP-вход не объединяет существующие локальные карточки с совпадающими логинами. Если LDAP отключен в настройках или недоступен, локальный вход сохраняется.

## Идентичность и доступ

Связь с AD хранится по уникальному objectGUID, поэтому переименование доменного логина не создает новую карточку. Внутренний логин создается в отдельном пространстве `ad:<GUID>`; пользователь вводит доменный логин, а не этот служебный ключ. Компания, роль, активность и объекты контролируются локально. Локально отключенная карточка не допускается ко входу. До назначения компании и роли рабочие страницы недоступны. Изменение профиля из AD обновляет только имя, фамилию и почту.

Для учетной записи AD установлен непригодный локальный пароль. Локальный способ входа и страница смены пароля ГПР не позволяют обойти проверку AD. Доменный пароль меняется в Windows либо через администратора AD. Отключение пользователя в AD проверяется при следующем LDAP-входе; для немедленного отключения в приложении нужно также деактивировать локальную карточку. Локальные учетные записи и вход суперпользователя сохраняются.

Миграция accounts/0009 добавляет источник входа и GUID. По умолчанию LDAP выключен до явной настройки окружения. Реальная доступность внутренней сети и принятие сервером Simple Bind проверяются на сервере ГПР; автоматические тесты используют подмененные LDAP-соединения и не доказывают доступность контроллеров домена.
